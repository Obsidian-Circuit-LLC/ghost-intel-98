# v3.41.0 — Compact Number Muncher + 512 MB viewer cap — Design

**Date:** 2026-07-10
**Origin:** GhostExodus field feedback on v3.40.0 (live Windows build, three screenshots).
**Repo:** `/dcs98` (core). Target **v3.41.0**. One batch.

## Feedback (verbatim intent)

1. Number Muncher "is functional :) Can you make it **much smaller**?" — referencing the **Windows 11 Calculator** beside it as the target footprint ("make it that size, or close to it… doesn't take up so much space").
2. My Documents viewer: "**All files open perfectly.** However, files over 64 MB are rejected. The PDF I was trying to open is **108 MB**. Is there a fix?"
3. Overall happy with the additions.

## Operator decisions (2026-07-10)

- **Compact layout = "Slim rail, no side column."** Drop the fixed 200 px right panel column. Keep the one-click mode rail (ADHD-friendly — see the standing GhostExodus low-friction constraint). Memory becomes a slim row; History hides behind a toggle; Info folds into a one-line status footer. Target ≈ **380×580**, close to the Win11 Calculator footprint.
- **Viewer cap = 512 MB** (was 64 MB). His 108 MB PDF opens with ~5× headroom; the graceful "too large — use Export" notice only fires for genuinely huge files.

## Charter

- **No new dependency, no egress.** Pure client-side layout change + one constant. My-Documents files stay encrypted at rest; the viewer still decrypts **in-process** (no OS handoff), now up to 512 MB.
- **Determinism / behavior preserved.** Every calculator engine is untouched — this is a shell/CSS reflow only. The memory-scope rule (Standard/Scientific only, disabled elsewhere) is preserved. All 7 modes keep working.

## Part 1 — Compact Number Muncher

**Current:** `.ga98-calc` is a `grid: auto 1fr 200px` (rail | keypad-main | side column) in a **760×620** window. The 200 px side column (Memory + History + Info panels) is the width driver.

**New:** `.ga98-calc` becomes `grid: auto 1fr` (rail | main) — no side column. Within `.ga98-calc-main`, top-to-bottom:

1. **Top bar** — the display, with a small **History toggle** button (🕘) pinned to its right.
2. **Memory row** — a slim horizontal strip of `MC MR MS M+ M-` plus a compact `M = {reg}` readout at the end (replaces the tall Memory panel). Disabled outside Standard/Scientific exactly as today (the v3.40.0 memory-scope rule).
3. **Keypad** — the existing per-mode keypad, unchanged, now filling the narrow body.
4. **Status footer** — one line replacing the 4-row Info panel: `{Mode} · 64-bit · {Status}` (e.g. `Standard · 64-bit · Ready`; shows `Error` when the display errors, and the last result inline when present).

**History** — toggled by the top-bar button; when on, a **drawer overlays the keypad area** (absolutely positioned inside `.ga98-calc-main`, scrollable, with its existing Clear control and a close/back). Off by default so the window stays compact and each mode's keypad is uncluttered. This mirrors the Win11 Calculator's history flyout.

**Window size:** `registerModule` `defaultWidth: 760 → 380`, `defaultHeight: 620 → 580`.

**All 7 modes** keep their keypads; the mode-specific dropdowns (Converter/Unit from/to selects, Date pickers, Statistics dataset list) go full-width in the narrower body. The slim rail keeps every mode one click away.

## Part 2 — 512 MB viewer cap

`store.ts`: `MAX_VIEW_BYTES = 64 * 1024 * 1024 → 512 * 1024 * 1024`. The message and the stat-before-read guard are unchanged (still refuses BEFORE decrypting, still surfaces "too large — use Export"). The case-attachment viewer path (`attachmentBytes.ts`, a **separate** paged path) keeps its own 64 MB cap — out of scope; only the My-Documents `readBytes` path is raised, per the report.

## Architecture / decomposition

- **Layout-only reflow.** No engine, no IPC, no store logic changes for Part 1 — the shell moves Memory/History/Info out of the side column into the main column (row / drawer / footer) and the grid loses its third track. The keypad components are untouched.
- **Cap is a one-constant change** with its covering test updated.

## Testing

- **Compact shell** (jsdom, `number-muncher-module.test.tsx`): the 7-mode rail still renders; there is **no** `.ga98-calc-side` column; the Memory row renders its 5 buttons and stays disabled outside Standard/Scientific; the History toggle shows/hides the history drawer; the status footer shows the active mode. Existing "2 + 3 = 5" drive test still passes.
- **Cap** (`documents-open-export.test.ts`): a file at 512 MB + 1 is rejected `/too large/i`; a 108 MB-class file (well under the cap) reads fine. (Update the existing 64 MB-boundary test to the new ceiling.)
- Full suite + typecheck green; grep the packaged asar to confirm the compact shell shipped.

## Out of scope (YAGNI)

- A Settings-configurable cap (512 MB flat; revisit only if a real file exceeds it).
- Raising the case-attachment (evidence) viewer cap — separate path, not reported.
- Any calculator engine or mode-behavior change.
- Persisting the History-drawer open/closed state across sessions.
