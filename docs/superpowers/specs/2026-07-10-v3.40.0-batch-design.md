## Operator decisions (2026-07-10)

- **Signature fix** — the draw-on-canvas pad; root cause found (display≠bitmap coords), fix implemented (`fc6bbe1`), folds into the batch.
- **Number Muncher** — a **full 7-mode** calculator (Standard · Scientific · Programmer · Converter · Statistics · Date Calc · Unit Calc) + memory + history, tucked into the **Organizer** menu category.
- **Rename** the Access-menu `Organization` category → **Organizer**.
- **My Documents internal viewer** — open files in Ghost Intel 98's own doc-viewer (no OS/Microsoft handoff); unsupported types get a notice + the existing **Export** fallback.

## Charter

- **No new dependency, no egress.** The calculator is pure client-side; the viewer reuses the existing `DocViewerModule` (pdfjs/mammoth already deps). My-Documents files stay encrypted at rest — the viewer reads decrypted bytes in-process, never handing off to the OS.
- **Determinism.** Every calculator engine is a pure function of its inputs (no `Date.now()` inside the pure math; Date Calc takes dates as inputs). Fully unit-tested.
- **Scoped.** New module `number-muncher`; the viewer generalization is additive (case source unchanged).

## Part 1 — Signature fix (done)

Root cause: `.ga98-sig-canvas` was flex-stretched to ~700px display while its bitmap is 280px, and `pos()` used unscaled coords → strokes landed off-bitmap. Fix: pin the canvas display to 280×80 + a pure `scaleToBitmap` coord mapping (unit-tested) + an explicit 2px stroke + pointer-capture. Already committed; carried in the batch branch.

## Part 2 — Organizer rename + Number Muncher in the menu

In `AccessMenu.tsx` `CATEGORIES`: rename the `Organization` entry's `label` to `Organizer`, and append `{ module: 'number-muncher', label: 'Number Muncher' }` to its `items` (after Invoices/Calendar/Reminders/Alarm). No other menu change.

## Part 3 — My Documents internal viewer

- **`DocViewerModule` gains a source discriminator.** Today it renders a case attachment (`{ caseId, fileName }`). Generalize its props to `{ source: 'case', caseId, fileName, originalName? } | { source: 'documents', relPath, name }`. The `case` path is unchanged. The `documents` path loads the file's **decrypted bytes** via a new main IPC `documents:readBytes(relPath)` (mirrors the case-attachment byte read; goes through the documents store's secure-fs decrypt), then feeds the same `kindFor(name)` → renderer pipeline (pdf/image/csv/json/html/docx/eml/text).
- **My Documents "Open" opens the viewer window** (`useWindows.open({ module: 'doc-viewer', title: name, props: { source: 'documents', relPath, name } })`) instead of the current decrypt-to-temp + `shell.openPath` OS handoff.
- **Unsupported types** (a `kind` the viewer can't render, or a genuinely-unviewable type like `.xlsx`/`.zip`): the viewer shows a **"Can't preview this file type in-app"** notice + an **Export…** button (the existing `documents:export` decrypt-to-chosen-path). No OS auto-handoff; the user chooses to take it out.
- The old temp-launch Open path is removed for My Documents (the Export path + the internal viewer replace it). Reveal-in-Explorer stays.

## Part 4 — Number Muncher (7-mode calculator)

A new `number-muncher` module (`src/renderer/modules/number-muncher/`) matching the mockup: a **mode rail** (left), a **Display** with the current value, per-mode **keypads**, a **Memory** panel (MC/MR/MS/M+/M−, showing the register), a **History** list (Clear History / Copy), and an **Info** panel (Mode / Precision: 64-bit / Last Result / Status). Win98-styled.

**Shared state (the shell):** current display string, the operand/operator machine, the memory register, the history list, the active mode, and (Scientific) the angle unit (deg/rad/grad). The shell owns state; each mode is a pure engine + a keypad that dispatches ops.

**Per-mode pure engines** (each in its own file, heavily unit-tested — the calculators' correctness is the priority):

- **`standard.ts`** — a small state machine: digit entry, `+ − × ÷`, `=`, `%`, `√`, `x²`, `1/x`, sign, decimal, backspace, CE/C. Deterministic; IEEE-754 with sane rounding for display.
- **`scientific.ts`** — extends standard with `sin/cos/tan` (+ inverse), `log/ln`, `10^x/e^x`, `x^y`, `n!`, `π`, `e`, and the deg/rad/grad angle mode (pure `toRadians(x, unit)`).
- **`programmer.ts`** — integer calculator over a chosen base (HEX/DEC/OCT/BIN): base conversion, `AND/OR/XOR/NOT`, `<< >>`, `MOD`, within a 64-bit width (BigInt-backed for exactness).
- **`converter.ts`** — number-base + common unit conversions via factor tables (`convert(value, from, to, category)`), categories with named units.
- **`statistics.ts`** — a dataset (list of numbers) → `mean/median/mode/sum/count/variance/stdev` (population + sample); pure over the list.
- **`date-calc.ts`** — `daysBetween(a, b)`, `addDays(date, n)`, `addMonths/Years`; pure (dates passed in, no `now()` inside).
- **`unit-calc.ts`** — categorized unit computation (length/mass/temperature/area/volume/speed/time); a factor/formula table (temperature needs offset formulas, not just factors).

**Memory + history** are shared pure helpers: `memoryOp(reg, op, current)` and `pushHistory(list, entry)` (bounded).

## Architecture / decomposition

- **Calculator = pure engines + thin components.** Each mode's math is a pure module (no DOM, no state) → unit tests assert exact results across cases. The keypad components dispatch ops to the shell reducer; the shell renders the display/memory/history/info. This keeps the 7 modes independently testable and buildable.
- **Viewer generalization is additive** — the `case` source path is untouched; only a new `documents` branch + one IPC + one bytes loader.
- **New module registration** follows the 5-point pattern (`register-builtins` + `ModuleKey` + `Icon` glyph + `Desktop` title + `types.ts`), plus the Access-menu Organizer entry.

## Testing

- Each engine (`standard/scientific/programmer/converter/statistics/date-calc/unit-calc`) — exhaustive pure unit tests (arithmetic correctness, edge cases: divide-by-zero, base overflow, temperature offsets, empty dataset, date boundaries, angle units).
- `memoryOp`/`pushHistory` — pure.
- The shell — renders the rail + panels; switching modes swaps the keypad; a computed result appends to history + updates the Info panel.
- Viewer — `documents` source renders a text/image file's bytes; an unsupported type shows the notice + Export; the `case` path is unchanged (regression).
- Menu — the category is "Organizer" and contains Number Muncher; the enumeration test still lists the `number-muncher` key.
- Signature — the `scaleToBitmap` tests (already present).

## Out of scope (YAGNI)

- Calculator theming/skins beyond the standard Win98 look.
- Graphing / equation solving / programmer float modes.
- A My-Documents *edit* path (view + export only).
- Converting the whole app's file-opening to the internal viewer (My Documents only; Cases already uses it).
