# W3 — GhostScrape credential race: per-job session isolation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`). Implementers run SEQUENTIALLY on the shared tree — never parallel.

**Goal:** Stop concurrent GhostScrape jobs from clobbering each other's X credentials, and surface a genuinely-failed capture instead of a silent empty success.

**Architecture:** Each scrape job runs in its own **non-persistent** Electron session partition (`ghostscrape-${jobId}`) instead of the shared `persist:ghostscrape`, so two jobs for different accounts can't overwrite one shared cookie jar. Plus honest error surfacing when capture never attached.

**Tech Stack:** Electron main process, TypeScript strict, Vitest. All changes confined to `src/main/x/ghostscrape/` (the X clearnet quarantine).
